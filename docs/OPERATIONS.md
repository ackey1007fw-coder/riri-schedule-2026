# 運用ガイド — 業務マップと自動化ロードマップ

このサイト（夏凪里季 応援スケジュール）の運用業務を整理し、AI・スクリプトで
どこまで自動化するかをまとめたドキュメント。2026-07 作成。

## 業務マップ

| 頻度 | 業務 | 入力 | 処理 | 出力 | 詰まりやすい点 |
|---|---|---|---|---|---|
| 日次 | SNS投稿の反映 | 投稿URL・本文・写真 | 画像取得→配置→news/photos/clips更新→QA→PR | サイト更新 | 画像取得の手作業、番号ミス、alt文作成、AI利用制限で中断 |
| 日次〜週次 | 動画クリップ追加 | TikTok/Instagram動画 | 動画DL→`public/videos/`→clips.ts | クリップ欄更新 | SNSからの自動取得不可（bot遮断） |
| 不定期 | 出演情報の追加 | 告知投稿・チラシ | 事実整理→events.ts→news.ts→QA→PR | スケジュール更新 | 日時・価格の転記ミス、演目混同 |
| 不定期 | プロフィール・ハイライト更新 | 受賞・メディア情報 | profile.ts / highlights.ts | 更新 | 未確認情報の混入リスク |
| 常時 | 2サイト並行運用 | — | main / yukako/main の使い分け | — | 取り違え（CI site-guard で対策済み） |
| 都度 | 品質確認 | 差分 | 型チェック・目視・プレビュー | マージ判断 | 目視頼みだった → qa スクリプトで機械化 |

**人間がやるべき判断**: 投稿を載せるかどうか / alt・紹介文のトーン / 事実確認（日時・価格）/ マージ承認。
**AI・スクリプトに任せる作業**: 画像取得・命名・配置 / 3ファイルへの定型追記 / 整合性検査 / コミット・PR作成。

## いま使えるツール

| コマンド | 何をするか |
|---|---|
| `npm run qa` | データ整合性検査（画像参照切れ・重複・日付形式・並び順・禁止表現） |
| `npm run images:fetch -- <DriveのID or URL>` | Drive画像を次のギャラリー番号で自動配置＋貼り付け用スニペット出力 |
| `npm run images:fetch -- <ID> --event <slug>` | イベント画像として `event-<slug>.jpg` に配置 |
| `/add-sns-post`（Claude Skill） | 投稿URL＋Drive IDを渡すと反映一式を実行 |
| `/add-event`（Claude Skill） | 出演情報の追加を定型化 |

CI: PRごとに `data-guard`（上のqa）+ `image-guard`（同名上書き禁止）+ `site-guard`（サイト取り違え検知）が走る。

## 標準フロー（明日からの運用）

1. りりの新規投稿を見つけたら、Drive「RiRi画像」に原本画像を置く（従来どおり）。
2. Claude に `/add-sns-post` + 投稿URL + DriveのファイルID（URLごとでも可）を渡す。
   - AI利用制限が近いときは自分で: `npm run images:fetch -- <ID...>` → 出力スニペットを photos.ts に貼る → news.ts 追記 → `npm run qa`。
3. PRのプレビュー（Vercel）を目視確認してからマージ。マージ判断は常に人間。

**中断リカバリ**: 途中で止まったら `git status` + `npm run qa`。
「未参照のギャラリー画像」警告 = 画像配置済み・データ未更新のサイン。そこから再開。

### 優先順位の考え方

- **Quick Win（済）**: #1-#7。毎日発生する反映作業そのものを直撃するため最優先で作成済み。
- **業務OS改善（次にやる）**: #14 yukako側への展開 → #13 → #16。
- **高難度挑戦（余力があるとき）**: #8 動画自動取得 → #10 プレビューSS → #15 月次集計。

## 安全ルール（変わらないもの）

- マージ・削除・上書き・外部投稿は必ず人間が承認する
- スクリプトはダウンロードと検査のみ。既存ファイルの上書き・削除はしない
- 認証情報をファイル・会話に書かない
- 絶対ルール（AGENTS.md）: 公式/公認と書かない・未確認情報を書かない・顔のAI生成禁止・差分最小・トリミング禁止
